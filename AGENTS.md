## Project state

- This project is an Odin port of the raylib C quickstart (converted from `src/main.c`); there is no C source left.
- Build with `make` (debug binary in `bin/debug/`); `make release`, `make run`, `make clean` also work. See the Makefile.
- The Odin source imports raylib via the bindings bundled with the Odin toolchain (`import "vendor:raylib"`), which links the prebuilt static lib from `$ODIN_ROOT/vendor/raylib/macos/`. (Raygui is NOT used; the inspector is hand-drawn rectangles.)
- On macOS the vendor `libraylib.a` symlink resolves through Homebrew's `/opt/homebrew/opt/raylib`; `libraygui-arm64.a` must be linked before `libraylib.a`, which Odin does automatically.
- On Windows, Odin links the prebuilt static `vendor/raylib/windows/raylib.lib` and `raygui.lib` automatically; no system libs or premake needed. `odin` must be on PATH (e.g. in the w64devkit terminal).
- Enemy waves (`update_enemy_waves` in `src/main.odin`): invoked every tick from `step_simulation`, so the wave clock and all `update_planet_combat` dogfight attrition only advance during unpaused play. Every `WAVE_INTERVAL` (120s) a wave of `WAVE_SIZE` (5) enemy fighters transits to a seeded-random target among Earth/Mars/Jupiter (`rl.GetRandomValue(0,2)`), so Earth itself can be hit. Combat pacing at the target planet: with both sides' fighters guarding there, one drone on each side is destroyed per second (5v5 lasts ~5s, 1:1 trade); with no player defenders left, one mining drone there dies per 2s. Surviving enemies then orbit until the player dispatches fighters to retake it. `N` forces a wave immediately (debug affordance, shown in the HUD status line).
- DANGER: do not run `premake5 gmake` or the old `build/*.bat` regenerate step — it overwrites the hand-written Odin `Makefile` with the C/C++ quickstart makefiles and `make` then fails with `undefined reference to WinMain` (no C source to provide an entry point). `build-MinGW-W64.bat` is already fixed to just run `make`.
- Logic tests live in `src/main_test.odin` (same package, excluded from `make` builds because Odin skips `*_test.odin` files) and run with `odin test src -define:ODIN_TEST_THREADS=1`. The single-threaded define is required: the tests mutate shared globals (`units`, timers) and the default parallel runner races them.
- Visual verification on this dev box: `screencapture` lacks screen-recording permission and window-compositor captures are stale. For headless visual checks, temporarily render into `rl.LoadRenderTexture` + `rl.LoadImageFromTexture` + `rl.ExportImage` (framebuffer export, no window server involved); pass relative filenames — raylib resolves them against the working directory.
- Game systems (constants in `src/main.odin`): player command bases exist only on Earth (`base_counts = {1,0,0}`); `start_base_construction`/`queue_unit` are gated on `selected_planet == 0`, and the inspector renders base/production/queue sections only for Earth (`draw_earth_inspector` vs `draw_outpost_inspector`). Jupiter starts enemy-occupied (garrison fighters/miners + 20 HP `enemy_base_hp`); a planet is liberated when its base hits 0, which the combat rules only allow after every enemy drone there is dead. Enemy waves: first at 180s then every 120s, each wave picks a seeded-random target among Earth/Mars/Jupiter (`rl.GetRandomValue(0,2)`, deterministic in tests via `rl.SetRandomSeed`). The Earth `Construct Command Base` button is hidden at the cap via `base_button_visible()` (`base_counts[0] < MAX_BASES || base_build_planet == 0`); a lost base brings it back, and clicking its area is a no-op at cap. Unit tiles in the inspector are compact (`TILE_SIZE` 26, `TILES_PER_ROW` 10, `TILE_GAP` 3): `draw_unit_tile` shows just the `M`/`C` symbol plus a corner state dot (no ordinal). Battles render short flying 3D laser bolts (`draw_combat_lasers` -> `draw_laser_bolt`, two phased bolts per ray, animated on `laser_anim_time` which only advances in `step_simulation`, so bolts freeze on pause): SKYBLUE for player fire, RED for enemy fire, mirroring `update_planet_combat` (dogfights, miner sweeps, base sieges). Base construction: Earth only, 200 minerals, queues immediately; miners already mining Earth join and returning miners auto-join on deposit (`.CONSTRUCTING`, retargeted to Earth) until `BASE_CONSTRUCT_MINERS` (5) — the 60s timer only runs with a full crew, then all resume `.MINING`. Mining is Earth round-trip based: transit out, mine `MINING_DURATION` (3s), transit back, deposit `DEPOSIT_DURATION` (0.5s) at `MINING_TRANSIT_SPEED` (1.75); `planet_mps` = min(active miners, `planet_mining_cap`) * `mining_rate` / (3.5 + 2*dist(p,Earth)/1.75), so MPS falls with distance. `mining_rate` = 10/10/25 and `planet_mining_cap` = 30/25/100 (Earth/Mars/Jupiter), enforced by `is_effective_miner` index ranking (payout + MPS; no Earth penalty). The Earth inspector also shows `global_mps()` (sum of all planets); roster headers show `roster_count`. The pause menu autosizes its box to `MeasureText` of the title/status lines (`pause_menu_rects`) so labels never overflow. Spacebar (`select_earth` from `update_input`) jumps the inspector to Earth. Pause is on P/F10 (`pause_key_pressed` in the main loop; ESC no longer pauses); ESC cancels the most recently queued build (`cancel_last_queued`, full refund). Build-queue slots are clickable to cancel by slot (`cancel_queued_at(0, slot)` — active production lines in base order first, then pending; cancelling a line promotes the first pending item); slot rects come from `queue_slot_rect`, shared by rendering and hitboxes. Mining drones hold `.IDLE` at an occupied planet until liberated, then resume; that `.IDLE` hold doubles as the scout survival clock — `kill_player_miner` never kills `.TRANSIT` miners (transit is safe) and grants a `SCOUT_SURVIVAL` (3.5s) grace before a pinned scout becomes a valid garrison target, so the player can peek at the garrison. Transit speeds: combat 2.5/s, mining 1.75/s (25% of the old pace); transit and guarding fighters render `ceil(count/10)` cubes per side/group. Fog of war is dynamic presence-based (`has_vision(p)` in `src/main.odin`): Earth is always lit; an off-world planet is visible only while a non-enemy unit is within `radius + 2.0` of it, so retreating/destroying the last unit there puts it back under fog. Enemy units at a fogged planet are fully concealed in 3D (`is_concealed`) and the outpost inspector shows `UNSCOUTED` (no enemy counts/base HP) — unless the planet was scouted before: `update_intel` (called per tick from `step_simulation`) snapshots enemy fighters/miners/base HP into `last_known_intel[p]` while `has_vision(p)`, and once the planet goes dark the inspector shows that stale snapshot as `LAST KNOWN INTEL`. Right-click on a planet is `handle_planet_right_click`: units selected → move order, no selection + Earth selected → set Earth rally flag (right-clicking Earth clears it). Initial camera altitude opens at 85% zoom (`CAMERA_START_Y = 42.75`).
- Tests live in `src/main_test.odin` (excluded from `make` builds automatically); run with `odin test src -define:ODIN_TEST_THREADS=1`. They drive pure logic (`update_enemy_waves`, `update_combat`, etc.) without a window; `reset_world()` reseeds raylib's RNG for deterministic wave targeting; `rl.GetRandomValue`/`rl.CheckCollisionPointRec` are pure math and safe in tests without a window; `rl.IsKeyPressed` reads false headless, so keybind tests assert the binding procs (`pause_key_pressed`, `cancel_last_queued`) rather than injected key events. `reset_world()` also clears production/pending/intel/`laser_anim_time`.
