## Project state

- This project is an Odin port of the raylib C quickstart (converted from `src/main.c`); there is no C source left.
- Build with `make` (debug binary in `bin/debug/`); `make release`, `make run`, `make clean` also work. See the Makefile.
- The Odin source imports raylib via the bindings bundled with the Odin toolchain (`import "vendor:raylib"`), which links the prebuilt static lib from `$ODIN_ROOT/vendor/raylib/macos/`. (Raygui is NOT used; the inspector is hand-drawn rectangles.)
- On macOS the vendor `libraylib.a` symlink resolves through Homebrew's `/opt/homebrew/opt/raylib`; `libraygui-arm64.a` must be linked before `libraylib.a`, which Odin does automatically.
- On Windows, Odin links the prebuilt static `vendor/raylib/windows/raylib.lib` and `raygui.lib` automatically; no system libs or premake needed. `odin` must be on PATH (e.g. in the w64devkit terminal).
- The system is eight planets in solar order, indexed by named constants (`MERCURY..NEPTUNE`, `EARTH :: 2`); Earth is the player's only starter planet. The outer three were shifted 80 units further left so Earth sits almost mid-pack — Saturn/Uranus/Neptune now sit at X -25/5/35 (30-unit X spacing kept; Jupiter's fixed x=50 bounds the right edge, giving a 3-left/4-right split around Earth, so X solar order no longer holds: Saturn floats left of Mercury at z=18) — and the **enemy HQ** fortress occupies Neptune's ORIGINAL orbit `{140, 5, 24}` (`ENEMY_HQ_POSITION`, `ENEMY_HOME :: PLANET_COUNT`, `SECTOR_COUNT :: PLANET_COUNT+1`), far off to the right by design. The HQ is a sector, not a planet: combat/timer/base-HP tables are sized `[SECTOR_COUNT]` so the same `update_planet_combat`/`planet_combatants`/`kill_fighter` logic works on it via `sector_pos`/`sector_radius` helpers (which return `planets[s]` for planets, the HQ for `ENEMY_HOME`). Every non-Earth sector opens occupied by the enemy, with garrison fighters/miners and base HP on a fixed occupation ladder (the `GARRISON_FIGHTERS`/`GARRISON_MINERS`/`GARRISON_BASE_HP` tables in `src/main.odin`, indexed by sector: Venus 10/4/10 ... Neptune 95/22/60, then the HQ 500/0/500 — after the Earth-centering shift the ladder no longer equals distance-from-Earth order). `initialize_game` and `reset_world` set `base_counts[EARTH] = 1` and `enemy_base_hp = GARRISON_BASE_HP`; standing garrisons are ~420 planetside + 500 HQ, so `MAX_UNITS :: 2560`.
- Enemy waves (`update_enemy_waves` in `src/main.odin`): invoked every tick from `step_simulation`, so the wave clock and all `update_planet_combat` dogfight attrition only advance during unpaused play. **All waves launch from the enemy HQ** (`spawn_n_enemies_to` spawns in a ring around `ENEMY_HQ_POSITION`; `home_planet = NEPTUNE`); a destroyed HQ launches nothing (`enemy_hq_destroyed()` guard in `spawn_n_enemies_to`). Regular waves scale with active mining: every `WAVE_INTERVAL` (120s; first at `WAVE_FIRST_DELAY` 180s) the game spawns **one wave per actively mined planet** (`mined_planet_count()` — distinct planets with a non-enemy, non-`.CONSTRUCTING` mining drone targeting them, any cycle phase), each wave striking its own mined world via `spawn_n_enemies_to` (distinct targets); minimum one default wave on a seeded-random target among all eight planets when nothing is mined, so Earth itself can be hit. Wave size is `attack_wave_size()`: `WAVE_SIZE` (5) fighters below `WAVE_DOUBLE_MIN_MINED_PLANETS` (4) mined planets, **doubled to 10 at 4+**. **Regular waves stop COMPLETELY at `MEGA_WAVE_MIN_MINED_PLANETS` (5) actively mined planets** — the regular clock only advances below that threshold. From 5+ on, only the **mega boss assault wave** (`mega_wave_timer`) runs: crossing the 5-mined-planet threshold fires the first `MEGA_WAVE_SIZE` (100)-fighter assault at a random world **immediately** (`mega_wave_armed` flag, no 300s wait), then every `MEGA_WAVE_INTERVAL_SECONDS` (300s) via `spawn_n_enemies`. Dropping below 5 mined planets instantly resets `mega_wave_timer` to 0 and disarms (`mega_wave_armed = false`); re-expanding fires a fresh immediate invasion. Combat pacing at the target planet: with both sides' fighters guarding there, one drone on each side is destroyed every `COMBAT_TICK` (0.2s — trades resolve 5x faster than the old 1s tick; 5v5 lasts 1s); with no player defenders left, one mining drone there dies per 0.2s. Surviving enemies then orbit until the player dispatches fighters to retake it. `N` forces a wave immediately (debug affordance, shown in the HUD status line).
- DANGER: do not run `premake5 gmake` or the old `build/*.bat` regenerate step — it overwrites the hand-written Odin `Makefile` with the C/C++ quickstart makefiles and `make` then fails with `undefined reference to WinMain` (no C source to provide an entry point). `build-MinGW-W64.bat` is already fixed to just run `make`.
- Logic tests live in `src/main_test.odin` (same package, excluded from `make` builds because Odin skips `*_test.odin` files) and run with `odin test src -define:ODIN_TEST_THREADS=1`. The single-threaded define is required: the tests mutate shared globals (`units`, timers) and the default parallel runner races them.
- Rendering (`draw_world` in `src/main.odin`): planets are clean solid `rl.DrawSphere` calls. SHARP EDGE: `rl.TextFormat` returns a `cstring` into a small rotating pool of static buffers (4 in stock raylib), so a `TextFormat` result is only valid until the next few `TextFormat` calls reuse its slot — never hold one across other `TextFormat` calls (format and draw/copy it first). This once clobbered the bottom-HUD status line: `status` was captured before `draw_squad_hud()` but drawn after it, and each squad badge's `TextFormat("[%d: %d]")` consumed a buffer, so a second saved squad overwrote the status string (FPS/controls vanished). Fix: draw `status` before `draw_squad_hud()`; `zoom_text` is safe because it is formatted and drawn immediately. — no grid, no `DrawSphereWires` wireframe overlay. The space backdrop is a deterministic starfield (`generate_stars`, `STAR_COUNT` 280, a fixed LCG seed independent of the gameplay RNG) of white dots in a wide disc below the play plane, drawn as screen-space `rl.DrawCircleV` pixels before the 3D pass so they sit behind everything; `draw_starfield` discards off-screen / NaN projections via `>=` bounds.
- Visual verification on this dev box: `screencapture` lacks screen-recording permission and window-compositor captures are stale. For headless visual checks, temporarily render into `rl.LoadRenderTexture` + `rl.LoadImageFromTexture` + `rl.ExportImage` (framebuffer export, no window server involved); pass relative filenames — raylib resolves them against the working directory.
- Game systems (constants in `src/main.odin`): player command bases exist only on Earth; `start_base_construction`/`queue_unit` are gated on `selected_planet == EARTH`, and the inspector renders base/production/queue sections only for Earth (`draw_earth_inspector` vs `draw_outpost_inspector`). A planet is liberated when its base hits 0, which the combat rules only allow after every enemy drone there is dead. The Earth `Construct Command Base` button is hidden at the cap via `base_button_visible()` (`base_counts[EARTH] < MAX_BASES || base_build_planet == EARTH`); a lost base brings it back, and clicking its area is a no-op at cap. Unit tiles in the inspector are compact (`TILE_SIZE` 26, `TILES_PER_ROW` 10, `TILE_GAP` 3): `draw_unit_tile` shows just the `M`/`C` symbol plus a corner state dot (no ordinal); the player MINING DRONES header shows `(<current>/<cap>)` via `planet_mining_cap` (plain count at the HQ, which hosts no mining). Battles render short flying 3D laser bolts (`draw_combat_lasers` -> `draw_laser_bolt`, two phased bolts per ray, animated on `laser_anim_time` which only advances in `step_simulation`, so bolts freeze on pause): SKYBLUE for player fire, RED for enemy fire, mirroring `update_planet_combat` (dogfights, miner sweeps, base sieges). Base construction: Earth only, `BASE_COST` (500) minerals, queues immediately; miners already mining Earth join and returning miners auto-join on deposit (`.CONSTRUCTING`, retargeted to Earth) until `BASE_CONSTRUCT_MINERS` (5) — the 60s timer only runs with a full crew, then all resume `.MINING`; recruitment prefers Earth-assigned drones first (`earth_assigned_miner_available`: target or affiliation EARTH) — a foreign-route depositor only soaks into the crew once no Earth-assigned miner remains. On completion the new line immediately pulls pending items via `fill_production_lines(p)` (the base-queue pickup fix), so a freshly finished base starts building the next queued unit without a new `queue_unit`. Drone build times are `MINER_BUILD_TIME` (6s) and `COMBAT_BUILD_TIME` (10s) base, scaled by `drone_build_time(kind)` = `base * math.pow(0.8, drone_speed_level)` — the drone build-speed upgrade (`purchase_drone_speed_upgrade`, Earth-only, `U` keybind + inspector button below the BUILD row; 5000 minerals/level, max 5 levels, compounds to ~33% of base time, `reset_world` zeroes it); the level shows in the top HUD bar (`SPEED LVL n/5`) and the queue grid / unit-tile rosters shifted down to clear the new button (`queue_slot_rect` queue_y +76, `unit_tile_y` Earth offset +147). Mining is Earth round-trip based: transit out, mine `MINING_DURATION` (4s), transit back, deposit `DEPOSIT_DURATION` (0.5s) at `MINING_TRANSIT_SPEED` (1.3125); `planet_mps` = min(active miners, `planet_mining_cap`) * `mining_rate` / (4.5 + 2*dist(p,Earth)/1.3125), so MPS falls with distance. `mining_rate` = 10 for the inner planets (Mercury/Venus/Earth/Mars), 25 for Jupiter and beyond; `planet_mining_cap` = 30 (Earth), 25 (Mercury/Venus/Mars), 100 (Jupiter+), enforced by `is_effective_miner` index ranking (payout + MPS; no Earth penalty). The Earth inspector also shows `global_mps()` (sum of all planets); roster headers show `roster_count`. The pause menu autosizes its box to `MeasureText` of the title/status lines (`pause_menu_rects`, sharing the `PAUSE_STATUS` constant so the label never drifts) so labels never overflow; it is keyboard-navigable — Up/Down move `pause_menu_selection` (0=CONTINUE, 1=QUIT) via `advance_pause_selection` (wraps), ENTER/KP_ENTER run `activate_pause_selection`, and `draw_pause_focus` draws a gold ring + `>` marker on the focused button; mouse clicks still work and `toggle_pause` resets focus to CONTINUE on open. The planet inspector shows enemy forces as a second set of roster sections (`ENEMY MINING DRONES (n)` / `ENEMY FIGHTING DRONES (n)`) via `enemy_in_roster`/`enemy_roster_count`/`enemy_roster_ordinal`/`enemy_tile_y`, rendered only while `has_vision(selected_planet)` and the section's count is > 0 (garrison drones at an occupied world or an attacking wave, even inbound); `draw_unit_tile` takes an `enemy` flag for the red-tinted tiles. Spacebar (`select_earth` from `update_input`) jumps the inspector to Earth. Pause is on P/F10 (`pause_key_pressed` in the main loop; ESC no longer pauses); ESC cancels the most recently queued build (`cancel_last_queued`, full refund). Control groups: `Shift+1..9` saves the current selection to squad `1..9` (`save_squad`), bare `1..9` recalls it (`recall_squad`); squad membership lives on a `Unit.squad` field (0 = none), so it auto-prunes as units are destroyed/shifted (no index bookkeeping). The global HUD top bar shows `MINERALS` + empire `global_mps()` and, below it, `draw_squad_hud` renders `[n: count]` badges for each assigned squad. Build-queue slots are clickable to cancel by slot (`cancel_queued_at(EARTH, slot)` — active production lines in base order first, then pending; cancelling a line promotes the first pending item); slot rects come from `queue_slot_rect`, shared by rendering and hitboxes. Mining drones hold `.IDLE` at an occupied planet until liberated, then resume; that `.IDLE` hold doubles as the scout survival clock — `kill_player_miner` never kills `.TRANSIT` miners (transit is safe) and grants a `SCOUT_SURVIVAL` (3.5s) grace before a pinned scout becomes a valid garrison target, so the player can peek at the garrison. Transit speeds: combat 2.5/s, mining 1.3125/s (25% below the warpace 1.75); transit and guarding fighters render `ceil(count/10)` cubes per side/group. Fog of war is dynamic presence-based (`has_vision(p)` in `src/main.odin`): Earth is always lit; an off-world planet is visible only while a non-enemy unit is within `radius + 2.0` of it, so retreating/destroying the last unit there puts it back under fog. Enemy units at a fogged planet are fully concealed in 3D (`is_concealed`) and the outpost inspector shows `UNSCOUTED` (no enemy counts/base HP) — unless the planet was scouted before: `update_intel` (called per tick from `step_simulation`) snapshots enemy fighters/miners/base HP plus the full roster (per-unit kind/state/enemy, `Intel.units`, cap 200) into `last_known_intel[p]` while `has_vision(p)`; once a scouted planet goes dark the inspector renders a dimmed GHOST view (`ghost_view` + `draw_ghost_rosters`: normal roster sections with unit tiles from the frozen snapshot, translucent overlay, amber STALE INTEL stronghold card; tile layout uses `view_count` so headers/hitboxes agree — tile clicks and box-select are disabled under ghost), never mutating while dark; never-scouted planets keep `UNSCOUTED`. Right-click on a planet is `handle_planet_right_click`: units selected → move order, no selection + Earth selected → set Earth rally flag (right-clicking Earth clears it). The rally sentinel is `NO_RALLY :: -1` (Earth no longer doubles as the 0 sentinel since the planet reindex). Initial camera: `camera_target = {10, 0, 2}` (center of the planet extents X -30..50 / Z -20..24), opening at 60% zoom (`CAMERA_START_Y = 89`) so all eight planets frame beside the 330px inspector panel at startup.
- **Enemy HQ & victory**: the HQ is picked via `hq_picked` (a separate ray-sphere test — `pick_planet` covers planets only). **Left-clicking the HQ selects it** (`selected_planet = ENEMY_HOME`): `draw_inspector` renders `draw_hq_inspector` (fortress status card: garrison fighters + structural integrity while lit, UNSCOUTED under fog, HUSK once destroyed) and the shared unit rosters work there, so fighters stationed at / bound for the HQ (`.COMBAT`, `affiliation == ENEMY_HOME`) appear in the roster, are click/box-selectable, and right-click recalls them to any planet (miners never appear — `issue_group_order` skips mining drones for `ENEMY_HOME`, and `set_earth_rally` refuses it). Victory (`victory_achieved`: every planet liberated AND `enemy_hq_destroyed`) latches in `step_simulation`; the main loop then freezes the sim and shows `draw_victory_overlay` ("CONGRATULATIONS! YOU BEAT THE GAME!") with two buttons — `[R] PLAY AGAIN` (`R`/`ENTER`/click → `restart_game` = `reset_world()` + `initialize_game()`) and `[Q] QUIT` (`Q`/`ESC`/click → `quit_requested`; ESC is free here since the sim is frozen and builds can't be cancelled on victory). `reset_world` lives in `src/main.odin` (shared by the restart path and the test suite; it also resets `earth_rally`, `victory`, `game_paused`, `mega_wave_armed`).
- Tests live in `src/main_test.odin` (excluded from `make` builds automatically); run with `odin test src -define:ODIN_TEST_THREADS=1`. They drive pure logic (`update_enemy_waves`, `update_combat`, etc.) without a window; `reset_world()` (in `src/main.odin`) reseeds raylib's RNG for deterministic wave targeting; `rl.GetRandomValue`/`rl.CheckCollisionPointRec` are pure math and safe in tests without a window; `rl.IsKeyPressed` reads false headless, so keybind tests assert the binding procs (`pause_key_pressed`, `cancel_last_queued`) rather than injected key events. `reset_world()` also clears production/pending/intel/`laser_anim_time`/`earth_rally`/`victory`/`game_paused`, sets `enemy_base_hp = GARRISON_BASE_HP` and `base_counts[EARTH] = 1` (no garrison units — tests that want the starting layout call `initialize_game()`).
