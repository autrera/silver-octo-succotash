## Project state

- This project is an Odin port of the raylib C quickstart (converted from `src/main.c`); there is no C source left.
- Build with `make` (debug binary in `bin/debug/`); `make release`, `make run`, `make clean` also work. See the Makefile.
- The Odin source imports raylib via the bindings bundled with the Odin toolchain (`import "vendor:raylib"`), which links the prebuilt static lib from `$ODIN_ROOT/vendor/raylib/macos/`. (Raygui is NOT used; the inspector is hand-drawn rectangles.)
- On macOS the vendor `libraylib.a` symlink resolves through Homebrew's `/opt/homebrew/opt/raylib`; `libraygui-arm64.a` must be linked before `libraylib.a`, which Odin does automatically.
- On Windows, Odin links the prebuilt static `vendor/raylib/windows/raylib.lib` and `raygui.lib` automatically; no system libs or premake needed. `odin` must be on PATH (e.g. in the w64devkit terminal).
- The system is eight planets in solar order, indexed by named constants (`MERCURY..NEPTUNE`, `EARTH :: 2`); Earth is the player's only starter planet. The outer three were shifted 80 units further left so Earth sits almost mid-pack — Saturn/Uranus/Neptune now sit at X -25/5/35 (30-unit X spacing kept; Jupiter's fixed x=50 bounds the right edge, giving a 3-left/4-right split around Earth, so X solar order no longer holds: Saturn floats left of Mercury at z=18) — and the **enemy HQ** fortress occupies Neptune's ORIGINAL orbit `{140, 5, 24}` (`ENEMY_HQ_POSITION`, `ENEMY_HOME :: PLANET_COUNT`, `SECTOR_COUNT :: PLANET_COUNT+1`), far off to the right by design. The HQ is a sector, not a planet: combat/timer/base-HP tables are sized `[SECTOR_COUNT]` so the same `update_planet_combat`/`planet_combatants`/`kill_fighter` logic works on it via `sector_pos`/`sector_radius` helpers (which return `planets[s]` for planets, the HQ for `ENEMY_HOME`). Every non-Earth sector opens occupied by the enemy, with garrison fighters/miners and base HP on a fixed occupation ladder (the `GARRISON_FIGHTERS`/`GARRISON_MINERS`/`GARRISON_BASE_HP` tables in `src/main.odin`, indexed by sector: Venus 10/4/10 ... Neptune 95/22/60, then the HQ 500/0/500 — after the Earth-centering shift the ladder no longer equals distance-from-Earth order). `initialize_game` and `reset_world` set `base_counts[EARTH] = 1` and `enemy_base_hp = GARRISON_BASE_HP`; standing garrisons are ~420 planetside + 500 HQ, so `MAX_UNITS :: 2560`.
- Enemy waves (`update_enemy_waves` in `src/main.odin`): invoked every tick from `step_simulation`, so the wave clock and all `update_planet_combat` dogfight attrition only advance during unpaused play. **All waves launch from the enemy HQ** (`spawn_n_enemies_to` spawns in a ring around `ENEMY_HQ_POSITION`; `home_planet = NEPTUNE`); a destroyed HQ launches nothing (`enemy_hq_destroyed()` guard in `spawn_n_enemies_to`). Waves need active mining: every `WAVE_INTERVAL` (180s; first at `WAVE_FIRST_DELAY` 180s) a **single** wave launches, but the clock only advances while `mined_planet_count()` reports 2+ worlds (`WAVE_MIN_MINING_PLANETS` — distinct planets with a non-enemy mining drone **actively in state `.MINING`** on them; transit/idle scouts and returning/depositing miners never count, so dispatching scouts can't trigger invasions). The wave is never random: it strikes the liberated planet closest to the HQ (`closest_liberated_planet_to_hq()`), with `attack_wave_size()` = (liberated planets − 1) × `WAVE_FIGHTERS_PER_LIBERATED` (15) fighters — 3 liberated worlds send 30. While player fighters press the HQ (`player_attacking_hq()`: stationed or inbound) and its defenders sit below `ENEMY_HQ_GARRISON` (500), the wave instead musters there as guarding defenders (`spawn_hq_defenders`); planet attacks resume once the garrison is whole. There is no mega-wave logic. Combat pacing at the target planet: with both sides' fighters guarding there, one drone on each side is destroyed every `COMBAT_TICK` (0.2s — trades resolve 5x faster than the old 1s tick; 5v5 lasts 1s); with no player defenders left, one mining drone there dies per 0.2s. Surviving enemies then orbit until the player dispatches fighters to retake it. `N` forces a wave immediately (debug affordance, shown in the HUD status line).
- DANGER: do not run `premake5 gmake` or the old `build/*.bat` regenerate step — it overwrites the hand-written Odin `Makefile` with the C/C++ quickstart makefiles and `make` then fails with `undefined reference to WinMain` (no C source to provide an entry point). `build-MinGW-W64.bat` is already fixed to just run `make`.
- Logic tests live in `src/main_test.odin` (same package, excluded from `make` builds because Odin skips `*_test.odin` files) and run with `odin test src -define:ODIN_TEST_THREADS=1`. The single-threaded define is required: the tests mutate shared globals (`units`, timers) and the default parallel runner races them.
- Rendering (`draw_world` in `src/main.odin`): planets are procedural textured sphere models (`init_planet_visuals` builds a per-pixel RGBA texture — `GenImageColor` base shaded in code by perlin luminance, latitude bands for gas giants, blotches + oceans for Earth — onto a `GenMeshSphere` model drawn with `DrawModelEx` spinning on `planet_spin`, which advances in `step_simulation` so spin freezes on pause; falls back to flat `DrawSphere` when visuals are uninitialized, i.e. headless tests), plus an atmosphere shell, sun glint, drone-orbit ring and Saturn's tilted rings; SHARP EDGE: `GenMeshSphere` generates vertices with the polar axis along Z and `u`/`x` as latitude; `init_planet_visuals` sets `model.transform = MatrixRotateX(DEG2RAD * -90)` so poles align to +Y (matching `planet_spin` around `{0, 1, 0}`), with cloud bands drawn along `x` (latitude) so gas giants show parallel horizontal belts instead of longitudinal slices; SHARP EDGE: `GenImagePerlinNoise` returns 8-bit grayscale, so the tint never reaches the GPU texture (planets render grey) unless `ImageFormat(&img, .UNCOMPRESSED_R8G8B8A8)` runs before `LoadTextureFromImage`; the HQ is a layered battlestation (`draw_hq_fortress`: stacked hull, tower, corner turrets, window band, pulsing beacon + radar sweep). SHARP EDGE: `rl.TextFormat` returns a `cstring` into a small rotating pool of static buffers (4 in stock raylib), so a `TextFormat` result is only valid until the next few `TextFormat` calls reuse its slot — never hold one across other `TextFormat` calls (format and draw/copy it first). This once clobbered the bottom-HUD status line: `status` was captured before `draw_squad_hud()` but drawn after it, and each squad badge's `TextFormat("[%d: %d]")` consumed a buffer, so a second saved squad overwrote the status string (FPS/controls vanished). Fix: draw `status` before `draw_squad_hud()`; `zoom_text` is safe because it is formatted and drawn immediately. — no grid, no `DrawSphereWires` wireframe overlay. The space backdrop is a deterministic starfield (`generate_stars`, `STAR_COUNT` 280, a fixed LCG seed independent of the gameplay RNG) of white dots in a wide disc below the play plane, drawn as screen-space `rl.DrawCircleV` pixels before the 3D pass so they sit behind everything; `draw_starfield` discards off-screen / NaN projections via `>=` bounds.

For headless visual checks, temporarily render into `rl.LoadRenderTexture` + `rl.LoadImageFromTexture` + `rl.ExportImage` (framebuffer export, no window server involved); pass relative filenames — raylib resolves them against the working directory.
- Game systems (constants in `src/main.odin`): player command bases exist only on Earth; `start_base_construction`/`queue_unit` are gated on `selected_planet == EARTH`, and the inspector renders base/production/queue sections only for Earth (`draw_earth_inspector` vs `draw_outpost_inspector`). A planet is liberated when its base hits 0, which the combat rules only allow after every enemy drone there is dead. The Earth `Command Base` button is hidden at the cap via `base_button_visible()` (`base_counts[EARTH] < MAX_BASES || base_build_planet == EARTH`), collapsing the production sections up to `SECTION_TOP` (`production_title_y`, `production_first_y`, `production_orders_y`, `BASE_COLLAPSE_Y` 74) to eliminate the empty gap; a lost base brings it back. Unit tiles in the inspector are compact (`TILE_SIZE` 16, `TILES_PER_ROW` 10, `TILE_GAP` 6): `draw_unit_tile` shows just the `M`/`C` symbol plus a corner state dot (no ordinal); the player MINING DRONES header shows `(<current>/<cap>)` via `planet_mining_cap` (plain count at the HQ, which hosts no mining). Battles render short flying 3D laser bolts (`draw_combat_lasers` -> `draw_laser_bolt`, two phased bolts per ray, animated on `laser_anim_time` which only advances in `step_simulation`, so bolts freeze on pause): NEON_CYAN for player fire, RED for enemy fire, mirroring `update_planet_combat` (dogfights, miner sweeps, base sieges). Base construction: Earth only, `BASE_COST` (500) minerals, queues immediately; miners already mining Earth join and returning miners auto-join on deposit (`.CONSTRUCTING`, retargeted to Earth) until `BASE_CONSTRUCT_MINERS` (5) — the 60s timer only runs with a full crew, then all resume `.MINING`; recruitment prefers Earth-assigned drones first (`earth_assigned_miner_available`: target or affiliation EARTH) — a foreign-route depositor only soaks into the crew once no Earth-assigned miner remains. On completion the new line immediately pulls pending items via `fill_production_lines(p)` (the base-queue pickup fix), so a freshly finished base starts building the next queued unit without a new `queue_unit`. Drone build times are `MINER_BUILD_TIME` (6s) and `COMBAT_BUILD_TIME` (10s) base, scaled by `drone_build_time(kind)` = `base * math.pow(0.8, drone_speed_level)` — the drone build-speed upgrade (`purchase_drone_speed_upgrade`, Earth-only, `U` keybind + inspector button below the BUILD row; 5000 minerals/level, max 5 levels, compounds to ~33% of base time, `reset_world` zeroes it); the level shows in the top HUD bar (`SPEED LVL n/5`) and the queue grid / unit-tile rosters shifted down to clear the new button (`queue_slot_rect` queue_y +108, `unit_tile_y` Earth offset +206). Mining is Earth round-trip based: transit out, mine `MINING_DURATION` (4s), transit back, deposit `DEPOSIT_DURATION` (0.5s) at `MINING_TRANSIT_SPEED` (1.3125); `planet_mps` = min(active miners, `planet_mining_cap`) * `mining_rate` / (4.5 + 2*dist(p,Earth)/1.3125), so MPS falls with distance. `mining_rate` = 10 for the inner planets (Mercury/Venus/Earth/Mars), 25 for Jupiter and beyond; `planet_mining_cap` = 30 (Earth), 25 (Mercury/Venus/Mars), 100 (Jupiter+), enforced by `is_effective_miner` index ranking (payout + MPS; no Earth penalty). Roster headers show `roster_count`. The pause menu autosizes its box to `MeasureText` of the title (`pause_menu_rects`, 5 buttons: 0=CONTINUE, 1=SAVE GAME, 2=LOAD GAME, 3=NEW GAME, 4=QUIT) so labels never overflow; it is keyboard-navigable via `advance_pause_selection` (wraps), ENTER/KP_ENTER run `activate_pause_selection`, and `draw_pause_focus` draws a neon ring on the focused button; `C`, `S`, `L`, `N`, `Q` directly trigger options, `F5` quick-saves during unpaused gameplay (triggers `hud_save_notification_timer`), and `toggle_pause` resets focus to CONTINUE on open. **Start menu & Save system**: the game opens in `in_start_menu` with a space background; `start_menu_rects`/`update_start_menu`/`draw_start_menu` offer `[N] NEW GAME`, `[Q] QUIT`, and `[C] CONTINUE` if `save_game_exists()`. Game state saves to plain text `savegame.txt` (mirrored in both working directory and next to the executable via `os.get_executable_directory`, gitignored) via `save_game`/`load_game` (`serialize_game_state`/`deserialize_game_state`: version, minerals, speed level, rally, camera, planet bases, production/pending, sectors, intel snapshot, and all units). The planet inspector shows enemy forces as a second set of roster sections (`ENEMY MINING DRONES (n)` / `ENEMY FIGHTING DRONES (n)`) via `enemy_in_roster`/`enemy_roster_count`/`enemy_roster_ordinal`/`enemy_tile_y`, rendered only while `has_vision(selected_planet)` and the section's count is > 0 (garrison drones at an occupied world or an attacking wave, even inbound); `draw_unit_tile` takes an `enemy` flag for the red-tinted tiles. Spacebar (`select_earth` from `update_input`) jumps the inspector to Earth. Pause is on P/F10 (`pause_key_pressed` in the main loop; ESC no longer pauses); ESC cancels the most recently queued build (`cancel_last_queued`, full refund). Control groups: `Shift+1..9` saves the current selection to squad `1..9` (`save_squad`), bare `1..9` recalls it (`recall_squad`); squad membership lives on a `Unit.squad` field (0 = none), so it auto-prunes as units are destroyed/shifted (no index bookkeeping). The global HUD top bar is a floating tech dock (`HUD_PAD` 16, `HUD_DOCK_H` 40, 24px column gaps with 20px NEON_DIM dividers); the bottom status line is a matching dock (`BOTTOM_DOCK_H` 36, size-12 text so the keybind guide never collides with the ZOOM/ALTITUDE readout) and `draw_squad_hud` renders compact `[n:count]` pills aligned flush with the top dock (`HUD_PAD` 16, `BADGE_Y` 68, `BADGE_H` 20).- The whole UI sits on an 8px-grid layout (`PANEL_PAD_X` 20, `PANEL_CONTENT_W` 290, section constants in `src/main.odin`); render procs and click hitboxes share the same rect helpers, so they cannot drift. **Sci-Fi Cyberpunk HUD UI Theme**: styled after clean futuristic vector HUD interfaces (`SCIFI_CYAN` #00F0D8, `SCIFI_MINT` #8CFFEB, `SCIFI_AMBER` #FF8024, `SCIFI_RED` #FF3C4B, translucent dark teal-black glass `SCIFI_PANEL` {6,16,22,240}). Visual primitives: `draw_chamfered_panel` (convex 8-sided polygon with 45° cut corners), `draw_corner_brackets` (outer corner L-accents framing windows, buttons, and reticles), `draw_segmented_meter` (discrete digital meter blocks `■■■□□` for progress, integrity, and upgrades), and `draw_optical_reticle_2d` (concentric circular segmented arc quadrants, cardinal crosshair ticks, outer targeting brackets, and center pip for celestial selection). Buttons (`draw_button`) use cut corners, centered text labels, and hover corner brackets (no arrows or text shifting). Build-queue slots are clickable to cancel by slot (`cancel_queued_at(EARTH, slot)` — active production lines in base order first, then pending; cancelling a line promotes the first pending item); slot rects come from `queue_slot_rect`, shared by rendering and hitboxes. Clean typography: all decorative slashes (`//`), arrows (`>>`, `>`), side grip notches, and protruding off-screen tabs are eliminated for maximum legibility and balanced spacing. Mining drones hold `.IDLE` at an occupied planet until liberated, then resume; that `.IDLE` hold doubles as the scout survival clock — `kill_player_miner` never kills `.TRANSIT` miners (transit is safe) and grants a `SCOUT_SURVIVAL` (3.5s) grace before a pinned scout becomes a valid garrison target, so the player can peek at the garrison. Transit speeds: combat 2.5/s, mining 1.3125/s (25% below the warpace 1.75); transit and guarding fighters render `ceil(count/10)` drone models per side/group (`draw_fighter_drone`: fuselage + nose cone + swept wings + cockpit + engine flare, oriented along the orbit tangent or transit heading, with engine trails in transit); miners render as `draw_miner_drone` (hull sphere + canopy + cargo pods + drill + glow) instead of plain cubes. Fog of war is dynamic presence-based (`has_vision(p)` in `src/main.odin`): Earth is always lit; an off-world planet is visible only while a non-enemy unit is within `radius + 2.0` of it, so retreating/destroying the last unit there puts it back under fog. Enemy units at a fogged planet are fully concealed in 3D (`is_concealed`) and the outpost inspector shows `UNSCOUTED` (no enemy counts/base HP or roster labels) — unless the planet was scouted before: `update_intel` (called per tick from `step_simulation`) snapshots enemy fighters/miners/base HP plus the full roster (per-unit kind/state/enemy, `Intel.units`, cap 200) into `last_known_intel[p]` while `has_vision(p)`; once a scouted planet goes dark the inspector renders a dimmed GHOST view (`ghost_view` + `draw_ghost_rosters`: normal roster sections with unit tiles from the frozen snapshot, translucent overlay, amber STALE INTEL stronghold card; tile layout uses `view_count` so headers/hitboxes agree — tile clicks and box-select are disabled under ghost), never mutating while dark; never-scouted planets keep `UNSCOUTED`. Right-click on a planet is `handle_planet_right_click`: units selected → move order, no selection + Earth selected → set Earth rally flag (right-clicking Earth clears it). The rally sentinel is `NO_RALLY :: -1` (Earth no longer doubles as the 0 sentinel since the planet reindex). Initial camera: `camera_target = {10, 0, 2}` (center of the planet extents X -30..50 / Z -20..24), opening at 60% zoom (`CAMERA_START_Y = 89`) so all eight planets frame beside the 330px inspector panel at startup.
- **Earth siege & defeat**: when enemies hold Earth with no player fighters or miners left (`player_miners_at(p)` gates it; transit miners are safe, mirroring `kill_player_miner`), `update_planet_combat`'s `enemies > 0` branch runs a base siege on `p == EARTH` only: `base_timer[p]` accumulates and `destroy_player_base(EARTH)` drops one command base every `BASE_SIEGE_TIME` (2s) — clearing its production line (`production[p][base_counts-1] = Production{}`) and re-running `fill_production_lines` so pending orders stay consistent (a freed line above the new cap stays out of service; pending items wait rather than promote into it). Defeat (`defeat_condition`: zero PLAYER units — enemy garrisons/waves occupy unit slots and must not block it — AND zero bases map-wide) latches `defeated` in `step_simulation`; the main loop freezes the sim and shows `draw_game_over_overlay` sharing the victory overlay's button rects/keys (`[R]` restart, `[Q]`/ESC quit).
- **Enemy HQ & victory**: the HQ is picked via `hq_picked` (a separate ray-sphere test — `pick_planet` covers planets only). **Left-clicking the HQ selects it** (`selected_planet = ENEMY_HOME`): `draw_inspector` renders `draw_hq_inspector` (fortress status card: garrison fighters + structural integrity while lit, UNSCOUTED under fog, HUSK once destroyed) and the shared unit rosters work there, so fighters stationed at / bound for the HQ (`.COMBAT`, `affiliation == ENEMY_HOME`) appear in the roster, are click/box-selectable, and right-click recalls them to any planet (miners never appear — `issue_group_order` skips mining drones for `ENEMY_HOME`, and `set_earth_rally` refuses it). Victory (`victory_achieved`: every planet liberated AND `enemy_hq_destroyed`) latches in `step_simulation`; the main loop then freezes the sim and shows `draw_victory_overlay` ("CONGRATULATIONS! YOU BEAT THE GAME!") with two buttons — `[R] PLAY AGAIN` (`R`/`ENTER`/click → `restart_game` = `reset_world()` + `initialize_game()`) and `[Q] QUIT` (`Q`/`ESC`/click → `quit_requested`; ESC is free here since the sim is frozen and builds can't be cancelled on victory). `reset_world` lives in `src/main.odin` (shared by the restart path and the test suite; it also resets `earth_rally`, `victory`, `game_paused`).
- Tests live in `src/main_test.odin` (excluded from `make` builds automatically); run with `odin test src -define:ODIN_TEST_THREADS=1`. They drive pure logic (`update_enemy_waves`, `update_combat`, etc.) without a window; `reset_world()` (in `src/main.odin`) reseeds raylib's RNG for deterministic wave targeting; `rl.GetRandomValue`/`rl.CheckCollisionPointRec` are pure math and safe in tests without a window; `rl.IsKeyPressed` reads false headless, so keybind tests assert the binding procs (`pause_key_pressed`, `cancel_last_queued`) rather than injected key events. `reset_world()` also clears production/pending/intel/`laser_anim_time`/`earth_rally`/`victory`/`game_paused`, sets `enemy_base_hp = GARRISON_BASE_HP` and `base_counts[EARTH] = 1` (no garrison units — tests that want the starting layout call `initialize_game()`).
