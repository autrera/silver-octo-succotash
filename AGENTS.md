## Project state

- This project is an Odin port of the raylib C quickstart (converted from `src/main.c`); there is no C source left.
- Build with `make` (debug binary in `bin/debug/`); `make release`, `make run`, `make clean` also work. See the Makefile.
- The Odin source imports raylib via the bindings bundled with the Odin toolchain (`import "vendor:raylib"`), which links the prebuilt static lib from `$ODIN_ROOT/vendor/raylib/macos/`. (Raygui is NOT used; the inspector is hand-drawn rectangles.)
- On macOS the vendor `libraylib.a` symlink resolves through Homebrew's `/opt/homebrew/opt/raylib`; `libraygui-arm64.a` must be linked before `libraylib.a`, which Odin does automatically.
- On Windows, Odin links the prebuilt static `vendor/raylib/windows/raylib.lib` and `raygui.lib` automatically; no system libs or premake needed. `odin` must be on PATH (e.g. in the w64devkit terminal).
- The system is eight planets in solar order, indexed by named constants (`MERCURY..NEPTUNE`, `EARTH :: 2`); Earth is the player's only starter planet. The outer three were shifted 80 units further left so Earth sits almost mid-pack - Saturn/Uranus/Neptune now sit at X -25/5/35 (30-unit X spacing kept; Jupiter's fixed x=50 bounds the right edge, giving a 3-left/4-right split around Earth, so X solar order no longer holds: Saturn floats left of Mercury at z=18) - and the **enemy HQ** fortress occupies Neptune's ORIGINAL orbit `{140, 5, 24}` (`ENEMY_HQ_POSITION`, `ENEMY_HOME :: PLANET_COUNT`, `SECTOR_COUNT :: PLANET_COUNT+1`), far off to the right by design. The HQ is a sector, not a planet: combat/timer/base-HP tables are sized `[SECTOR_COUNT]` so the same `update_planet_combat`/`planet_combatants`/`kill_fighter` logic works on it via `sector_pos`/`sector_radius` helpers (which return `planets[s]` for planets, the HQ for `ENEMY_HOME`). Every non-Earth sector opens occupied by the enemy, with garrison fighters/miners and base HP on a fixed occupation ladder (the `GARRISON_FIGHTERS`/`GARRISON_MINERS`/`GARRISON_BASE_HP` tables in `src/main.odin`, indexed by sector: Venus 10/4/10 ... Neptune 95/22/60, then the HQ 500/0/500 - after the Earth-centering shift the ladder no longer equals distance-from-Earth order). `initialize_game` sets `base_counts[EARTH] = 1`, spawns 1 player mining drone and 5 player combat drones on Earth, and populates non-Earth garrisons; `reset_world` resets base counts to Earth 1 and `enemy_base_hp = GARRISON_BASE_HP`; standing garrisons are ~420 planetside + 500 HQ, so `MAX_UNITS :: 2560`.
- Enemy attacks (`update_enemy_waves` in `src/main.odin`): invoked every tick from `step_simulation`, so wave clocks and all `update_planet_combat` dogfight attrition only advance during unpaused play. Two distinct attack types exist:
  - **Minor wave** (`update_minor_wave`, `launch_minor_wave`): launches every 75s (`MINOR_WAVE_INTERVAL`). Independent of mined planets or wave timers. The closest unliberated planet to Earth (`closest_unliberated_planet_to_earth()`) launches 5 enemy combat drones (`MINOR_WAVE_SIZE`) against the closest liberated planet to the attacker (`closest_liberated_planet_to(attacker)`), not Earth unless Earth is the closest. 3 seconds before launch, the targeted planet receives an ominous red glow at half battle intensity (`minor_wave_warning_planet()`). This warning glare does not stop on launch: it persists while enemy drones are in transit (`planet_under_attack_warning()`, `combat_nebula_intensity` target 0.5) and transitions smoothly into the full battle glare (target 1.0) once enemy drones arrive and combat begins. Minor wave fighters spawn and transit together in a tight wedge formation equidistant from the target with individual orbit angles and individual 3D transit lines/models. If all planets are liberated, no minor wave launches.
  - **Wave** (`update_wave`, `launch_wave`): launches every `WAVE_INTERVAL` (180s; first at `WAVE_FIRST_DELAY` 180s) from the enemy HQ (`spawn_n_enemies_to` spawns in a ring around `ENEMY_HQ_POSITION`; `home_planet = NEPTUNE`). The wave clock advances while `liberated_planet_count()` reports 2+ worlds (`WAVE_MIN_LIBERATED_PLANETS` - Earth plus at least one liberated off-world planet). Strikes the liberated planet closest to the HQ (`closest_liberated_planet_to_hq()`), with `attack_wave_size()` = (liberated planets - 1) * `WAVE_FIGHTERS_PER_LIBERATED` (15) fighters - 3 liberated worlds send 30. While player fighters press the HQ (`player_attacking_hq()`: stationed or inbound) and its defenders sit below `ENEMY_HQ_GARRISON` (500), the wave instead musters there as guarding defenders (`spawn_hq_defenders`); planet attacks resume once the garrison is whole. A destroyed HQ launches nothing (`enemy_hq_destroyed()` guard).
  - Combat pacing at the target planet: with both sides' fighters guarding there, one drone on each side is destroyed every `COMBAT_TICK` (0.2s - trades resolve 5x faster than the old 1s tick; 5v5 lasts 1s); with no player defenders left, one mining drone there dies per 0.2s. Surviving enemies then orbit until the player dispatches fighters to retake it. `Ctrl+N` forces a wave immediately (debug affordance).

- Rendering (`draw_world` in `src/main.odin`): planets are procedural textured sphere models (`init_planet_visuals` builds a per-pixel RGBA texture - `GenImageColor` base shaded in code by perlin luminance, latitude bands for gas giants, blotches + oceans for Earth - onto a `GenMeshSphere` model drawn with `DrawModelEx` spinning on `planet_spin`, which advances in `step_simulation` so spin freezes on pause; falls back to flat `DrawSphere` when visuals are uninitialized, i.e. headless tests), plus an atmosphere shell, sun glint, drone-orbit ring and Saturn's tilted rings; SHARP EDGE: `GenMeshSphere` generates vertices with the polar axis along Z and `u`/`x` as latitude; `init_planet_visuals` sets `model.transform = MatrixRotateX(DEG2RAD * -90)` so poles align to +Y (matching `planet_spin` around `{0, 1, 0}`), with cloud bands drawn along `x` (latitude) so gas giants show parallel horizontal belts instead of longitudinal slices; SHARP EDGE: `GenImagePerlinNoise` returns 8-bit grayscale, so the tint never reaches the GPU texture (planets render grey) unless `ImageFormat(&img, .UNCOMPRESSED_R8G8B8A8)` runs before `LoadTextureFromImage`; the HQ is a layered battlestation (`draw_hq_fortress`: stacked hull, tower, corner turrets, window band, pulsing beacon + radar sweep). SHARP EDGE: `rl.TextFormat` returns a `cstring` into a small rotating pool of static buffers (4 in stock raylib), so a `TextFormat` result is only valid until the next few `TextFormat` calls reuse its slot - never hold one across other `TextFormat` calls (format and draw/copy it first). This once clobbered the bottom-HUD status line: `status` was captured before `draw_squad_hud()` but drawn after it, and each squad badge's `TextFormat("[%d: %d]")` consumed a buffer, so a second saved squad overwrote the status string (FPS/controls vanished). Fix: draw `status` before `draw_squad_hud()`; `zoom_text` is safe because it is formatted and drawn immediately. - no grid, no `DrawSphereWires` wireframe overlay. The space backdrop is a deterministic starfield (`generate_stars`, `STAR_COUNT` 280, a fixed LCG seed independent of the gameplay RNG) of white dots in a wide disc below the play plane, drawn as screen-space `rl.DrawCircleV` pixels before the 3D pass so they sit behind everything; `draw_starfield` discards off-screen / NaN projections via `>=` bounds. **Combat nebulae** (`draw_combat_nebulae` in `src/main.odin`): a red palpitating cosmic nebula is drawn in screen space right before `rl.BeginMode3D` behind planets where drones are actively fighting (`sector_in_combat`: dogfights, miner sweeps, base sieges) and behind the enemy HQ fortress. Rendered in 2D before the 3D pass, the 3D textured planet sphere and fortress models naturally occlude the nebula core while luminous multi-tiered crimson gas clouds (`.ADDITIVE` blending, 12 asymmetric billowing lobes across 3 tiers, ambient shroud, hot corona, and ionization filaments) expand into background space; palpitates on multi-harmonic breathing pulses (combining fundamental + second harmonic) and transitions smoothly via `combat_nebula_intensity[SECTOR_COUNT]`, ramping up in battle and fading out upon victory/destruction; radii, lobe spans, and viewport bounds are halved for a clean, tight warzone envelope. **Earth industrial indicator** (`draw_earth_industry_lights` in `src/main.odin`): when units are in production or base construction is active on Earth, industrial facilities across 10 continental coordinates light up. Screen-space additive rendering projects surface positions with globe occlusion/limb-fade checks, displaying pulsating foundry furnaces, cyan/mint automated assembly bays with alternating shift cycles, staccato robotic welding sparks, hazard strobes, and vertical shipyard gantry spires with blinking warning beacons. Transitions smoothly via `earth_industry_intensity` (+dt*2.8 ramp, -dt*1.8 decay).

- Frame pacing & VSYNC: with `.VSYNC_HINT` enabled, never call `rl.SetTargetFPS(60)`. Raylib's internal `EndDrawing` frame-limiter calls `WaitTime` (`nanosleep`) after `glfwSwapBuffers`; on macOS/Windows kernel timer granularity causes `WaitTime` to oversleep by 1-2ms, repeatedly missing the 16.67ms VBLANK swap deadline and dropping the display presentation cadence to exactly 30 FPS. Setting `SetTargetFPS(target_fps * 2)` acts as an upper safety cap for unconstrained runs while preventing `WaitTime` from sleeping during VSYNC-locked presentation.
- 3D drone rendering & performance: `build_miner_model` and `build_fighter_model` bake procedural drone geometries into static GPU meshes once at startup (`init_drone_visuals` / `unload_drone_visuals`). Drones render representationally per side and group (`rep_count` = `ceil(count/10)`) for both fighters and miners (`draw_fighter_drone`, `draw_miner_drone`), reducing 3D draw calls by up to 90% in large armies. Frame-rate optimizations for late-game (1500+ units): `planet_mps` and `global_mps` use a single linear pass early-breaking at `planet_mining_cap` (eliminating O(N^2) scans in HUD/inspector); `draw_world` consolidates over 75 per-sector/side loops into 2 linear passes over `unit_count` using preallocated `world_sector_spots` (`[SECTOR_COUNT]World_Sector_Spots`) with `draw_combat_lasers` receiving pre-collected spots; `draw_inspector`, `box_select`, and `click_unit_tiles` precompute `unit_tile_y` and `enemy_tile_y` outside per-unit loops; `draw_squad_hud` tallies squad counts in a single pass instead of 9 passes; `update_intel` updates all lit planets in 1 pass instead of 24; `has_vision` uses squared-distance checks; and `sector_in_combat` exits early at the first combatant pair and is cached in `sector_combat_state` for combat nebulae.

Defeat (`defeat_condition`: zero PLAYER units — enemy garrisons/waves occupy unit slots and must not block it — AND zero bases map-wide) latches `defeated` in `step_simulation`; the main loop freezes the sim and shows `draw_game_over_overlay` sharing the victory overlay's button rects/keys (`[R]` restart, `[Q]`/ESC quit).
- **Enemy HQ & victory**: the HQ is picked via `hq_picked` (a separate ray-sphere test — `pick_planet` covers planets only). **Left-clicking the HQ selects it** (`selected_planet = ENEMY_HOME`): `draw_inspector` renders `draw_hq_inspector` (fortress status card: garrison fighters + structural integrity while lit, UNSCOUTED under fog, HUSK once destroyed) and the shared unit rosters work there, so fighters stationed at / bound for the HQ (`.COMBAT`, `affiliation == ENEMY_HOME`) appear in the roster, are click/box-selectable, and right-click recalls them to any planet (miners never appear — `issue_group_order` skips mining drones for `ENEMY_HOME`, and `set_earth_rally` refuses it). Victory (`victory_achieved`: every planet liberated AND `enemy_hq_destroyed`) latches in `step_simulation`; the main loop then freezes the sim and shows `draw_victory_overlay` ("CONGRATULATIONS! YOU BEAT THE GAME!") with two buttons — `[R] PLAY AGAIN` (`R`/`ENTER`/click → `restart_game` = `reset_world()` + `initialize_game()`) and `[Q] QUIT` (`Q`/`ESC`/click → `quit_requested`; ESC is free here since the sim is frozen and builds can't be cancelled on victory). `reset_world` lives in `src/main.odin` (shared by the restart path and the test suite; it also resets `earth_rally`, `victory`, `game_paused`).
- Tests live in `src/main_test.odin` (excluded from `make` builds automatically); run with `odin test src -define:ODIN_TEST_THREADS=1`. They drive pure logic (`update_enemy_waves`, `update_combat`, etc.) without a window; `reset_world()` (in `src/main.odin`) reseeds raylib's RNG for deterministic wave targeting; `rl.GetRandomValue`/`rl.CheckCollisionPointRec` are pure math and safe in tests without a window; `rl.IsKeyPressed` reads false headless, so keybind tests assert the binding procs (`pause_key_pressed`, `cancel_last_queued`) rather than injected key events. `reset_world()` also clears production/pending/intel/`laser_anim_time`/`earth_rally`/`victory`/`game_paused`, sets `enemy_base_hp = GARRISON_BASE_HP` and `base_counts[EARTH] = 1` (no garrison units — tests that want the starting layout call `initialize_game()`).
