## Project state

- This project is an Odin port of the raylib C quickstart (converted from `src/main.c`); there is no C source left.
- Build with `make` (debug binary in `bin/debug/`); `make release`, `make run`, `make clean` also work. See the Makefile.
- The Odin source imports raylib via the bindings bundled with the Odin toolchain (`import "vendor:raylib"`), which links the prebuilt static lib from `$ODIN_ROOT/vendor/raylib/macos/`. (Raygui is NOT used; the inspector is hand-drawn rectangles.)
- On macOS the vendor `libraylib.a` symlink resolves through Homebrew's `/opt/homebrew/opt/raylib`; `libraygui-arm64.a` must be linked before `libraylib.a`, which Odin does automatically.
- On Windows, Odin links the prebuilt static `vendor/raylib/windows/raylib.lib` and `raygui.lib` automatically; no system libs or premake needed. `odin` must be on PATH (e.g. in the w64devkit terminal).
- The system is eight planets in solar order, indexed by named constants (`MERCURY..NEPTUNE`, `EARTH :: 2`); Earth is the player's only starter planet. Every other planet opens occupied by the enemy, with garrison fighters/miners and base HP scaling up with distance from Earth (the `GARRISON_FIGHTERS`/`GARRISON_MINERS`/`GARRISON_BASE_HP` tables in `src/main.odin`, Venus 10/4/10 ... Neptune 95/22/60). `initialize_game` and `reset_world` set `base_counts[EARTH] = 1` and `enemy_base_hp = GARRISON_BASE_HP`; the standing garrisons are ~420 units, so `MAX_UNITS :: 2048`.
- Enemy waves (`update_enemy_waves` in `src/main.odin`): invoked every tick from `step_simulation`, so the wave clock and all `update_planet_combat` dogfight attrition only advance during unpaused play. Regular waves scale with active mining: every `WAVE_INTERVAL` (120s; first at `WAVE_FIRST_DELAY` 180s) the game spawns **one wave per actively mined planet** (`mined_planet_count()` — distinct planets with a non-enemy, non-`.CONSTRUCTING` mining drone targeting them, any cycle phase), each wave striking its own mined world via `spawn_n_enemies_to` (distinct targets); minimum one default wave on a seeded-random target among all eight planets when nothing is mined, so Earth itself can be hit. Wave size is `attack_wave_size()`: `WAVE_SIZE` (5) fighters below `WAVE_DOUBLE_MIN_MINED_PLANETS` (4) mined planets, **doubled to 10 at 4+**. A separate **mega boss assault wave** (`mega_wave_timer`) only advances while `mined_planet_count() >= MEGA_WAVE_MIN_MINED_PLANETS` (5); every `MEGA_WAVE_INTERVAL_SECONDS` (300s) it spawns `MEGA_WAVE_SIZE` (100) fighters at a random world via `spawn_n_enemies`. Dropping below 5 mined planets instantly resets `mega_wave_timer` to 0; re-expanding restarts it fresh from 0. Combat pacing at the target planet: with both sides' fighters guarding there, one drone on each side is destroyed per second (5v5 lasts ~5s, 1:1 trade); with no player defenders left, one mining drone there dies per 2s. Surviving enemies then orbit until the player dispatches fighters to retake it. `N` forces a wave immediately (debug affordance, shown in the HUD status line).
- DANGER: do not run `premake5 gmake` or the old `build/*.bat` regenerate step — it overwrites the hand-written Odin `Makefile` with the C/C++ quickstart makefiles and `make` then fails with `undefined reference to WinMain` (no C source to provide an entry point). `build-MinGW-W64.bat` is already fixed to just run `make`.
- Logic tests live in `src/main_test.odin` (same package, excluded from `make` builds because Odin skips `*_test.odin` files) and run with `odin test src -define:ODIN_TEST_THREADS=1`. The single-threaded define is required: the tests mutate shared globals (`units`, timers) and the default parallel runner races them.
- Rendering (`draw_world` in `src/main.odin`): planets are clean solid `rl.DrawSphere` calls. SHARP EDGE: `rl.TextFormat` returns a `cstring` into a small rotating pool of static buffers (4 in stock raylib), so a `TextFormat` result is only valid until the next few `TextFormat` calls reuse its slot — never hold one across other `TextFormat` calls (format and draw/copy it first). This once clobbered the bottom-HUD status line: `status` was captured before `draw_squad_hud()` but drawn after it, and each squad badge's `TextFormat("[%d: %d]")` consumed a buffer, so a second saved squad overwrote the status string (FPS/controls vanished). Fix: draw `status` before `draw_squad_hud()`; `zoom_text` is safe because it is formatted and drawn immediately. — no grid, no `DrawSphereWires` wireframe overlay. The space backdrop is a deterministic starfield (`generate_stars`, `STAR_COUNT` 280, a fixed LCG seed independent of the gameplay RNG) of white dots in a wide disc below the play plane, drawn as screen-space `rl.DrawCircleV` pixels before the 3D pass so they sit behind everything; `draw_starfield` discards off-screen / NaN projections via `>=` bounds.
- Visual verification on this dev box: `screencapture` lacks screen-recording permission and window-compositor captures are stale. For headless visual checks, temporarily render into `rl.LoadRenderTexture` + `rl.LoadImageFromTexture` + `rl.ExportImage` (framebuffer export, no window server involved); pass relative filenames — raylib resolves them against the working directory.
- Game systems (constants in `src/main.odin`): player command bases exist only on Earth; `start_base_construction`/`queue_unit` are gated on `selected_planet == EARTH`, and the inspector renders base/production/queue sections only for Earth (`draw_earth_inspector` vs `draw_outpost_inspector`). A planet is liberated when its base hits 0, which the combat rules only allow after every enemy drone there is dead. The Earth `Construct Command Base` button is hidden at the cap via `base_button_visible()` (`base_counts[EARTH] < MAX_BASES || base_build_planet == EARTH`); a lost base brings it back, and clicking its area is a no-op at cap. Unit tiles in the inspector are compact (`TILE_SIZE` 26, `TILES_PER_ROW` 10, `TILE_GAP` 3): `draw_unit_tile` shows just the `M`/`C` symbol plus a corner state dot (no ordinal). Battles render short flying 3D laser bolts (`draw_combat_lasers` -> `draw_laser_bolt`, two phased bolts per ray, animated on `laser_anim_time` which only advances in `step_simulation`, so bolts freeze on pause): SKYBLUE for player fire, RED for enemy fire, mirroring `update_planet_combat` (dogfights, miner sweeps, base sieges). Base construction: Earth only, `BASE_COST` (500) minerals, queues immediately; miners already mining Earth join and returning miners auto-join on deposit (`.CONSTRUCTING`, retargeted to Earth) until `BASE_CONSTRUCT_MINERS` (5) — the 60s timer only runs with a full crew, then all resume `.MINING`. On completion the new line immediately pulls pending items via `fill_production_lines(p)` (the base-queue pickup fix), so a freshly finished base starts building the next queued unit without a new `queue_unit`. Drone build times are `MINER_BUILD_TIME` (6s) and `COMBAT_BUILD_TIME` (10s) base, scaled by `drone_build_time(kind)` = `base * math.pow(0.8, drone_speed_level)` — the drone build-speed upgrade (`purchase_drone_speed_upgrade`, Earth-only, `U` keybind + inspector button below the BUILD row; 5000 minerals/level, max 5 levels, compounds to ~33% of base time, `reset_world` zeroes it); the level shows in the top HUD bar (`SPEED LVL n/5`) and the queue grid / unit-tile rosters shifted down to clear the new button (`queue_slot_rect` queue_y +76, `unit_tile_y` Earth offset +147). Mining is Earth round-trip based: transit out, mine `MINING_DURATION` (4s), transit back, deposit `DEPOSIT_DURATION` (0.5s) at `MINING_TRANSIT_SPEED` (1.3125); `planet_mps` = min(active miners, `planet_mining_cap`) * `mining_rate` / (4.5 + 2*dist(p,Earth)/1.3125), so MPS falls with distance. `mining_rate` = 10 for the inner planets (Mercury/Venus/Earth/Mars), 25 for Jupiter and beyond; `planet_mining_cap` = 30 (Earth), 25 (Mercury/Venus/Mars), 100 (Jupiter+), enforced by `is_effective_miner` index ranking (payout + MPS; no Earth penalty). The Earth inspector also shows `global_mps()` (sum of all planets); roster headers show `roster_count`. The pause menu autosizes its box to `MeasureText` of the title/status lines (`pause_menu_rects`, sharing the `PAUSE_STATUS` constant so the label never drifts) so labels never overflow; it is keyboard-navigable — Up/Down move `pause_menu_selection` (0=CONTINUE, 1=QUIT) via `advance_pause_selection` (wraps), ENTER/KP_ENTER run `activate_pause_selection`, and `draw_pause_focus` draws a gold ring + `>` marker on the focused button; mouse clicks still work and `toggle_pause` resets focus to CONTINUE on open. The planet inspector shows enemy forces as a second set of roster sections (`ENEMY MINING DRONES (n)` / `ENEMY FIGHTING DRONES (n)`) via `enemy_in_roster`/`enemy_roster_count`/`enemy_roster_ordinal`/`enemy_tile_y`, rendered only while `has_vision(selected_planet)` and the section's count is > 0 (garrison drones at an occupied world or an attacking wave, even inbound); `draw_unit_tile` takes an `enemy` flag for the red-tinted tiles. Spacebar (`select_earth` from `update_input`) jumps the inspector to Earth. Pause is on P/F10 (`pause_key_pressed` in the main loop; ESC no longer pauses); ESC cancels the most recently queued build (`cancel_last_queued`, full refund). Control groups: `Shift+1..9` saves the current selection to squad `1..9` (`save_squad`), bare `1..9` recalls it (`recall_squad`); squad membership lives on a `Unit.squad` field (0 = none), so it auto-prunes as units are destroyed/shifted (no index bookkeeping). The global HUD top bar shows `MINERALS` + empire `global_mps()` and, below it, `draw_squad_hud` renders `[n: count]` badges for each assigned squad. Build-queue slots are clickable to cancel by slot (`cancel_queued_at(EARTH, slot)` — active production lines in base order first, then pending; cancelling a line promotes the first pending item); slot rects come from `queue_slot_rect`, shared by rendering and hitboxes. Mining drones hold `.IDLE` at an occupied planet until liberated, then resume; that `.IDLE` hold doubles as the scout survival clock — `kill_player_miner` never kills `.TRANSIT` miners (transit is safe) and grants a `SCOUT_SURVIVAL` (3.5s) grace before a pinned scout becomes a valid garrison target, so the player can peek at the garrison. Transit speeds: combat 2.5/s, mining 1.3125/s (25% below the warpace 1.75); transit and guarding fighters render `ceil(count/10)` cubes per side/group. Fog of war is dynamic presence-based (`has_vision(p)` in `src/main.odin`): Earth is always lit; an off-world planet is visible only while a non-enemy unit is within `radius + 2.0` of it, so retreating/destroying the last unit there puts it back under fog. Enemy units at a fogged planet are fully concealed in 3D (`is_concealed`) and the outpost inspector shows `UNSCOUTED` (no enemy counts/base HP) — unless the planet was scouted before: `update_intel` (called per tick from `step_simulation`) snapshots enemy fighters/miners/base HP into `last_known_intel[p]` while `has_vision(p)`, and once the planet goes dark the inspector shows that stale snapshot as `LAST KNOWN INTEL`. Right-click on a planet is `handle_planet_right_click`: units selected → move order, no selection + Earth selected → set Earth rally flag (right-clicking Earth clears it). The rally sentinel is `NO_RALLY :: -1` (Earth no longer doubles as the 0 sentinel since the planet reindex). Initial camera altitude opens at 85% zoom (`CAMERA_START_Y = 42.75`).
- Tests live in `src/main_test.odin` (excluded from `make` builds automatically); run with `odin test src -define:ODIN_TEST_THREADS=1`. They drive pure logic (`update_enemy_waves`, `update_combat`, etc.) without a window; `reset_world()` reseeds raylib's RNG for deterministic wave targeting; `rl.GetRandomValue`/`rl.CheckCollisionPointRec` are pure math and safe in tests without a window; `rl.IsKeyPressed` reads false headless, so keybind tests assert the binding procs (`pause_key_pressed`, `cancel_last_queued`) rather than injected key events. `reset_world()` also clears production/pending/intel/`laser_anim_time`, sets `enemy_base_hp = GARRISON_BASE_HP` and `base_counts[EARTH] = 1` (no garrison units — tests that want the starting layout call `initialize_game()`).
